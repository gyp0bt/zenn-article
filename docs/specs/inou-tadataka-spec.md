# 伊能忠敬計画 — 詳細仕様書

> [README.md](../../README.md) へ戻る | [ロードマップ](../roadmap.md)

## 1. プロジェクト概要

マッチングアプリ（Tinder）の「全国カバレッジ最適化」問題。日本全土のTinderユーザーを漏れなくスワイプするために、所在地設定の最適な配置と巡回順序を求める。

静的な集合被覆問題ではなく、**ユーザーが時間とともに再生成される動的被覆問題**として定式化する。「掃除しても汚れていく」パトロール型の最適巡回問題。

### 記事のトーン

- 「全国のTinderユーザーをコンプリートしたい」という荒唐無稽な動機を入口に、被覆問題・TSP・動的最適化の数理的美しさを展開する
- 2021年の先行実験の泥臭い試行錯誤を率直に語りつつ、数学的に洗練された解法へ昇華させる
- 技術基調の重厚感と、壮大な探索計画を立てるワクワク感を両立

## 2. 先行実験（2021年）の知見

### 2.1 実験概要

- **手法**: ブラウザ上でJavaScriptを直接実行し、Tinderの自動スワイプを実施
- **スワイプレート**: 約1回/秒（≒86,400回/日）
- **出発地点**: 都市部
- **日本地図二値化・ランダムサンプリング**: Python
- **ログデータ**: 残存なし（再現実験が必要）

### 2.2 発見された課題

#### 課題1: 幾何的被覆ギャップ

Tinderの探索範囲は所在地からユーザー設定距離内の円（最大約160km）。ある地点をスワイプしきった後、隣接する地点として現在の円に**接する**円を選ぶと、2円の間にスワイプ残りが発生する。

```
    ○○          接点付近にギャップ
   ○  ○  ○○
  ○    ○○  ○
  ○    ○○  ○   ← 2つの円の隙間にいるユーザーが漏れる
   ○  ○  ○○
    ○○
```

接する2つの半径$R$の円の間の最大ギャップ幅は、円の中心間距離$d$に対して：
- 接する場合（$d = 2R$）: ギャップは理論上0だが、実際には離散的なユーザー分布で漏れが生じる
- 重なりを持たせると（$d < 2R$）: 重複スワイプが増加し非効率

#### 課題2: ユーザーの動的再生成

- 都市圏を優先的にスワイプしても、**数日かかる間に既スワイプ地域に新規ユーザーが参入**する
- 出戻り（アプリを一度やめて戻ってきた）ユーザーも再出現する
- つまり、スワイプ完了した地域もユーザーが**一定レートで再蓄積**していく
- **静的な被覆問題ではなく、時間発展する動的問題**

#### 課題3: 探索効率の地域差

- 都市部: ユーザー密度が高く、1地点で3日ほどかかる
- 地方: ユーザー密度が低く、短時間でスワイプしきれる
- ランダムサンプリングでは人口密度を考慮できず、効率が悪かった

### 2.3 ゴール定義

> **ある瞬間に日本全土のどの地点を選んでも、未スワイプユーザーが存在しない（または理論上最小である）状態を達成すること。**

## 3. 数理モデル

### 3.1 基本設定

| 記号 | 意味 | 値/備考 |
|------|------|---------|
| $\Omega$ | 日本の陸地領域 | GISデータから取得 |
| $R$ | Tinderの探索半径 | 可変パラメータ（最大約160 km）。最適値を導出する |
| $\rho(\mathbf{x})$ | 地点 $\mathbf{x}$ の人口密度 | 国勢調査データ |
| $\lambda(\mathbf{x})$ | 地点 $\mathbf{x}$ のユーザー再生成レート | $\lambda(\mathbf{x}) = \alpha \cdot \rho(\mathbf{x})$ |
| $s$ | スワイプレート | 1 回/秒 = 86,400 回/日（BAN回避の上限） |

### 3.2 静的被覆問題（第一段階）

**入力**: 日本の陸地領域 $\Omega$、探索半径 $R$（決定変数として扱う）

**目的**: $\Omega$ を半径 $R$ の円で被覆するための最小地点集合 $P = \{p_1, \ldots, p_n\}$ を求める。

$$\min |P| \quad \text{s.t.} \quad \Omega \subseteq \bigcup_{i=1}^{n} B(p_i, R)$$

ここで $B(p, R)$ は中心 $p$、半径 $R$ の円（球面上の測地円）。

**探索半径のトレードオフ**: $R$は決定変数。$R$を大きくすると被覆地点数$|P|$は減少するが、各地点のユーザー数が増加し滞在時間が伸びる。動的問題と合わせて最適$R$を導出する。

**人口重み付き被覆**: ユーザーが存在しない地域（海上、山岳部など）は被覆不要。人口密度 $\rho(\mathbf{x})$ をしきい値で二値化し、被覆対象領域を絞り込む。

$$\Omega' = \{\mathbf{x} \in \Omega \mid \rho(\mathbf{x}) > \rho_{min}\}$$

### 3.3 動的被覆問題（第二段階）

ユーザーの再生成を考慮した動的モデル。

#### ユーザー蓄積モデル

地点 $p_i$ における未スワイプユーザー数 $u_i(t)$ の時間発展：

$$\frac{du_i}{dt} = \lambda_i - s \cdot \mathbb{1}[i = c(t)]$$

- $\lambda_i = \int_{B(p_i, R)} \lambda(\mathbf{x}) d\mathbf{x}$: 地点 $p_i$ のカバー領域内のユーザー再生成レート
- $c(t)$: 時刻 $t$ にスワイプ中の地点
- $\mathbb{1}[\cdot]$: 指示関数（スワイプ中の地点のみ減少）

#### 滞在時間

地点 $p_i$ の蓄積ユーザーを全てスワイプするのに必要な滞在時間：

$$\tau_i = \frac{u_i(t_{arrive})}{s - \lambda_i}$$

ただし $s > \lambda_i$（スワイプレートが再生成レートを上回る）が成立する場合。$s \leq \lambda_i$ の地点では永遠にスワイプしきれない。

#### 移動コスト

地点 $p_i$ から $p_j$ への移動時間 $T_{ij}$（Tinderの所在地変更操作 + 反映待ち）。Tinderの仕様上、所在地変更は即座に可能と仮定すると $T_{ij} \approx 0$。

#### 最適巡回問題

巡回順序 $\sigma$ を決定変数として、全地点のスワイプ完了後に残る未スワイプユーザーの最大値を最小化する：

$$\min_{\sigma} \max_{i=1}^{n} u_i(t_{end})$$

これは**時間窓付きTSP (TSP with Time Windows)**の変種であり、かつ**再生成のあるパトロール問題 (Patrolling Problem with Regeneration)**として位置づけられる。

### 3.4 均衡条件

理想状態: 全地点のユーザー蓄積量が均一になるような**定常巡回パターン**が存在するか。

地点数 $n$、巡回周期 $T_{cycle}$ の定常状態では：

$$u_i^{max} = \lambda_i \cdot (T_{cycle} - \tau_i)$$

全地点の最大蓄積量を均一化する条件：

$$\lambda_1 \cdot (T_{cycle} - \tau_1) = \lambda_2 \cdot (T_{cycle} - \tau_2) = \cdots = \lambda_n \cdot (T_{cycle} - \tau_n)$$

これが実現可能かどうかは、$\{\lambda_i\}$ の分布に依存する。

## 5. 技術設計

### 5.1 技術スタック

## 6. 記事ごとの詳細計画

### 記事 #1: 問題設定と先行実験

**目的**: 2021年の先行実験を振り返り、問題の面白さと難しさを読者に伝える。

**構成**:
1. 導入: 「日本全土のTinderユーザーをコンプリートしたい」という野望
2. 先行実験の概要: 都市部での自動スワイプ（1回/秒、3日で完了）
3. 課題の発見:
   - 幾何的被覆ギャップ（接する円の隙間）
   - ユーザーの動的再生成（掃除しても汚れていく）
   - 地域差による探索効率のばらつき
4. ゴールの再定義: 「瞬間最大未スワイプ数の最小化」
5. 次回予告: 日本地図をデータとして扱う

**成果物**: 問題の概念図（mermaidまたは手描き風ダイアグラム）

### 記事 #2: 日本地図の二値化と人口密度

**目的**: GISデータと人口データの前処理パイプラインを構築する。

**構成**:
1. 国土数値情報からの日本地図取得
2. 人口メッシュデータの読み込み・可視化
3. 被覆対象領域の特定（人口密度しきい値による二値化）
4. 可変半径円でのカバレッジシミュレーション基盤の構築

**成果物**: 二値化地図、人口密度ヒートマップのPythonコード

### 記事 #3: 集合被覆問題としての定式化

**目的**: 静的な最小円被覆問題を定式化し、解く。

**構成**:
1. 集合被覆問題（Set Cover Problem）の数学的定式化
2. 候補地点の生成（格子点 or 人口重心）
3. 貪欲法による近似解
4. 整数計画法（ILP）による厳密解
5. 解の比較と可視化

**成果物**: 被覆最適化コード、最適配置の地図可視化

### 記事 #4: 最適配置の導出と静的解の限界

**目的**: 静的解を提示した上で、「これでは十分でない」ことを示す。

**構成**:
1. 最適配置結果の詳細分析（何地点で日本全土をカバーできるか）
2. 各地点のスワイプ所要時間の推定
3. 全地点を巡回した場合の総所要時間
4. 動的問題の示唆: 巡回中にユーザーが再蓄積する問題の提起
5. 次回予告: 動的モデルの導入

**成果物**: 静的最適解の可視化、所要時間の見積もり

### 記事 #5: ユーザー再生成モデル

**目的**: ユーザーの再生成を考慮した動的モデルを構築する。

**構成**:
1. 再生成レートの推定手法（公開統計データ + 短期再実験からの推計）
2. 微分方程式モデル（§3.3）
3. 滞在時間の計算と「スワイプしきれない」条件の分析
4. シミュレーションによるユーザー蓄積ダイナミクスの可視化

**成果物**: 動的モデルの実装、蓄積ダイナミクスの可視化

### 記事 #6: パトロール問題としての定式化

**目的**: 再生成を考慮した巡回スケジューリング問題を定式化する。

**構成**:
1. パトロール問題（Patrolling Problem）の概説
2. 均衡条件の導出（§3.4）
3. 巡回頻度の最適化: 人口密度に応じた訪問頻度の割り当て
4. 実行可能性の判定: 1人のスワイプ速度で全国カバーは可能か？

**成果物**: パトロールスケジューリングコード

### 記事 #7: 最適巡回ルートの導出

**目的**: 最終的な最適ルートを導出し、ゴール達成可能性を評価する。

**構成**:
1. 動的TSPソルバーによる最適巡回の計算
2. 定常状態のシミュレーション: 巡回を繰り返した際の収束挙動
3. ゴール達成可能性: 理論的限界と現実的な到達点
4. 感度分析: スワイプレート・再生成レートへの依存性
5. まとめ: 伊能忠敬は日本を踏破できたか

**成果物**: 最適ルートの地図上可視化、収束挙動のグラフ

## 7. 推定パラメータ

先行実験と2026年現行仕様に基づく。記事執筆時に精緻化する。

| パラメータ | 推定値 | 根拠 |
|-----------|--------|------|
| 探索半径 $R$ | 決定変数（最大160 km） | Tinderのユーザー設定可能範囲。最適値を導出する |
| スワイプレート $s$ | 86,400 回/日 | 1回/秒 × 24時間（BAN回避上限） |
| 都市部の枯渇時間 | 約3日（$R$依存） | 先行実験（2021年、$R$不明） |
| 都市部のユーザー数推定 | 約260,000 人 | $86400 \times 3$（先行実験からの概算） |
| 再生成レート | 未定 | ログなし。公開統計 + 再実験から推定（記事#5） |
| 被覆地点数 | 未定 | $R$の関数として導出（記事#3-4） |
| Passport所在地変更 | 即時・無制限 | 2026年仕様。$T_{ij} \approx 0$ |
| 可視性重複 | 最大24時間 | 所在地変更後、旧地点のユーザーに24時間表示が継続 |
